# Stakeholder Mapping

| Stakeholder | Role and responsibilities | Needs / expectations | Impact of automation |
|---|---|---|---|
| End users / requesters | Submit network requests and provide business justification | Simple form, clear status, timely updates | Easier submission and better visibility |
| Approvers | Review risk, justification, and policy compliance; approve or reject | Relevant request details, clear decisions, audit history | Structured routing and traceable approvals |
| IT / ServiceNow administrators | Configure platform, access, data, and workflows | Reliable configuration, access control, maintainability | Less repetitive administration and consistent processing |
| Network fulfillment team | Execute approved work, update notes, and close tasks | Complete request details, correct assignment, clear priority | Better task assignment and fewer missing details |
| Project evaluator / mentor | Review project requirements, implementation, and evidence | Clear documentation, reproducible tests, visible repository | Easier evaluation of scope and progress |
| Security / compliance (consulted) | Define controls for sensitive access and audit requirements | Least privilege, approvals, traceability | More consistent enforcement and review evidence |

## Communication plan
- Requesters receive submission and status notifications.
- Approvers receive an actionable approval notification.
- Fulfillment teams receive assignment notifications.
- Administrators review operational reports and exceptions.
- The project mentor reviews documentation, screenshots, and test evidence.

## Access and responsibility principles
Use role-appropriate access. Requesters should not be able to approve their own requests unless a documented policy explicitly permits it. Administrative privileges should be limited to trusted administrators. Actual network changes must follow organizational change and security policies.
